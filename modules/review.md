# Review｜筛选与正式评分

## 选题轻检
按 [Planning](planning.md) 红线逐题检查，再比较实际观看理由、德夫业务价值与素材条件；不得用生成顺序或 `[:10]` 冒充筛选。

## 单题五稿评审（**交付前必经**）
先读取 [Writing](writing.md)。对**每一份**候选稿分别判断：
1. **消费者价值**：是否能让目标读者产生美感、向往、兴趣、有用理解或决策帮助？只堆材料知识、且与读者需要无关的不通过。审美型不强制认知反转，知识型不强制煽情。
2. **表达吸引力**：封面标题有没有点击理由、开头能否留住人、正文是否具体自然？不同版本是否真的有创意区别？
3. **事实与可发布性**：图片/案例/材料主张是否有证据，是否夸张或误导？未经核验的重大断言不能入选。
4. **格式**：每版有封面标题、正文≤150字符（含标点），无默认视频脚本。

必须形成**5条逐稿评审记录**（可为内部工作记录），给每篇明确保留/淘汰与具体原因；不能看完5稿就直接截前三篇。对通过者横向比较，优选3份（合格不足3份则只交合格稿并说明）。用户默认只看到**3份完整入选图文**及一句简短排序理由；用户明确要求查看全部时，展示5份并标记评审结论。

可运行 Python 的环境使用 [交付校验脚本](../scripts/validate_copy_review.py) 检查“五稿逐评、选稿数量、正文字符数”。脚本只能验证过程记录和格式，不能证明文案真正优质；不能运行时不得谎称已通过程序验证。

## 其他
一般审稿给最关键的1–3个问题及最小修改；未要求改稿不擅改。用户明确要正式 task/script/video 评分时读取 [scoring](../references/scoring.md) 和相应业务真源，轻检不冒充正式评分。
