# Review｜轻检、审稿、正式评分
先判断用户要哪一种，不将其混用：
- **批量轻检**：仅检查事实/素材边界、主题与观看理由、可制作性，输出“通过 / 自动修一轮 / 待补证 / 放弃”及一句原因。低风险项自动修一轮即可；高风险主张不得自动放行。无需六维分数。
- **审稿**：依 [content-system](../references/content-system.md) 定位影响最大的 1–3 个问题并给最小修改；用户没要求改稿就不擅改。
- **正式评分**：严格遵循 [scoring](../references/scoring.md)；task/script/video 三阶段分别使用工作区既有现行标准。证据不足不编分、不折算、不用总分抵消红线。

量产时避免“生成→打分→重写→无限重评”。每条自动修改最多一次；仍未通过的标明问题并交人工决定。素材授权、误导案例及无依据公开承诺始终需验证。用户指定正式复评时才进行下一次评分。
